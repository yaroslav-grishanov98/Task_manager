Что такое class Meta?
class Meta: - это внутренний класс, который ты определяешь внутри своей модели Django. Его цель — дать Django дополнительные инструкции о твоей модели, которые не связаны напрямую с полями, сохраняемыми в базе данных.

Зачем он нужен?
Он используется для конфигурации поведения модели. Без него Django использовал бы настройки по умолчанию, которые не всегда оптимальны. Meta позволяет "тонко настроить" твою модель.

Какие параметры можно определить в class Meta?
Вот некоторые из наиболее часто используемых и важных параметров:

verbose_name и verbose_name_plural:
Что делает: Определяет человекочитаемое (более понятное для пользователя) имя для твоей модели.
Зачем: Используется в админ-панели Django (например, "Задача" вместо "Task"), в сообщениях об ошибках, в названии форм и т.д. Если не указан, Django использует имя класса (Task) с заменой подчеркиваний на пробелы и переводом в нижний регистр.

ordering:
Что делает: Указывает порядок сортировки по умолчанию для объектов этой модели, когда они извлекаются из базы данных (например, при вызове Task.objects.all()).
Зачем: Гарантирует, что данные всегда будут представлены в предсказуемом порядке без необходимости каждый раз указывать .order_by().
Как использовать: Это кортеж или список строк. Каждая строка — это имя поля. Для сортировки по убыванию добавь минус перед именем поля (-field_name).

unique_together:
Что делает: Enforce unique constraints on multiple fields taken together. То есть, комбинация указанных полей должна быть уникальной.
Зачем: Для предотвращения дублирования записей, когда уникальность определяется не одним полем, а сочетанием нескольких.
Пример: Если у тебя есть модель Order, и ты хочешь, чтобы комбинация customer и order_date была уникальной (один клиент не может сделать два заказа в одну и ту же дату).

class Order(models.Model):
    customer = models.ForeignKey(User, on_delete=models.CASCADE)
    order_date = models.DateField()
    # ...
    class Meta:
        unique_together = [['customer', 'order_date']]

abstract:
Что делает: Если установлено в True, то эта модель не будет создаваться как отдельная таблица в базе данных. Вместо этого, она будет служить базовым классом, и все её поля будут добавлены в дочерние (унаследованные) модели.
Зачем: Pattern для DRY (Don't Repeat Yourself) - если у тебя есть общие поля, которые встречаются во многих моделях.

    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)
    class Meta:
        abstract = True

class BlogPost(BaseModel):
    title = models.CharField(max_length=200)
    # ... BlogPost будет иметь поля created_at и updated_at из BaseModel
app_label:
Что делает: Указывает, к какому приложению "принадлежит" модель.
Зачем: Обычно Django автоматически определяет это по имени папки приложения. Используется, когда модель определена вне стандартной структуры приложения или для переопределения названия приложения, к которому относится модель.
index_together:
Что делает: Определяет, какие поля вместе должны составлять индекс в базе данных.
Зачем: Для оптимизации запросов к базе данных, когда ты часто фильтруешь по комбинации этих полей.
Примечание: В современных версиях Django часто предпочитают использовать indexes (более гибко).
indexes:
Что делает: Явно определяет индексы базы данных для полей или комбинаций полей.
Зачем: Более гибкий способ создания индексов, чем index_together, позволяющий задавать дополнительные параметры индекса.

Здесь Meta класс говорит Django:

Когда ты видишь Task в единственном числе для пользователя, называй это "Задача".
Когда ты видишь Task во множественном числе для пользователя, называй это "Задачи".
Когда ты делаешь выборку всех задач (Task.objects.all()) без явного указания сортировки, сначала отсортируй их по due_date (сначала самые ранние), а если due_date одинаковый, то отсортируй по priority (где low < medium < high).
Класс Meta помогает сделать твои Django-приложения более структурированными, удобными для пользователя и оптимизированными.
